# 采集设备证据（交互式）

调用方只需一句话现象；设备与复现时间都可省略。默认只读、最小集：`bugreport` + 现象截图。**不要长篇规划或解释命令；对话保持简短（确认门除外）。**

1. **设备与时间**
   - 设备未给：先 `adb devices`；恰好 1 台直接用并把序列号报给调用方；多台必须问清，不得自动挑选；一台都没有时，若给了 IP 就 `adb connect <IP>:5555`。
   - 时间可模糊/省略；事后证据只写发生范围，未知写“待补充”。
   - 调用方已给出设备并说“开始采集/复现完成/确认”时，视为已确认：直接执行，不再追问。
2. **确认门（唯一一次）**
   - 未确认时只回一行：
     `设备：<序列号>；采集：bugreport + 截图；现在开始？回复“开始采集”（现场复现则回复“复现完成”）。`
   - 收到明确确认前，只允许 `adb devices` 枚举；**不得执行任何采集命令**。
3. **采集（只读；全部带 `-s` 或确保仅一台在线）**
   - `adb -s <序列号> bugreport <输出目录>`
   - `adb -s <序列号> exec-out screencap -p > <输出目录>/screen.png`
   - 录屏默认不做；调用方明确要求，或现象为闪烁/动画/卡顿时才可选 `screenrecord` + `adb pull`。
   - 仅当现象明确属于某子系统时追加单条额外项（蓝牙 HCI snoop、显示/音频/网络 dumpsys 头部、tombstone 摘要）；不要扩成套件。
   - 设备不在线时 `adb connect <IP>:5555`。
4. **事后证据（D 模式）**
   - 调用方说没有设备/不在现场/已有 bugreport 时：**不连接设备、不执行任何设备命令**，只校验并打包已有文件。
   - 发生时间只写范围；未知写“待补充”；bugreport 超 24MB 时生成时间窗摘录包。
5. **打包与草稿**
   - 产物写 `data/intake/<日期>-<slug>/`；`summary.md` 含现象、设备、时间（可范围/模糊）、每项用途与 SHA-256；zip 总大小 ≤24MB；超限生成时间窗摘录包并说明。
   - 生成 `issue-draft.md`：标题 `<现象摘要>（<系统版本号>）`；正文含现象、时间线、环境、复现步骤（推测，未确认）、预期/实际、附件清单（只列文件名与用途，**不写 SHA-256**）、下次偶现采集建议、AI 取证声明；不写内网地址。
   - 调用方明确说“不采集”：只生成草稿并标注“未采集证据”，不走确认门/采集。
6. **输出（≤5 行）**
   ```text
   完成：<zip 路径>（<大小>）
   文件：bugreport.zip、screen.png
   草稿：<issue-draft.md 路径>（标题：...）
   提交：粘贴草稿正文，拖入 zip 与截图
   取回：docker cp openfde-ai:/workspace/data/intake/<slug> .
   ```
   - **不要**在对话中输出 issue 草稿全文、哈希表、命令清单或长解释；调用方要全文时再给。
   - 在宿主/VM 直接运行时，取回行改为本机路径；在容器内运行时用 `docker cp`（容器名 `openfde-ai`）。
   - 无法 adb 时给出 PC 端命令 3 行以内，不生成脚本。

边界：只读（bugreport/screencap/screenrecord/白名单 pull）；禁止 root、禁止 `logcat -c`、禁止安装/卸载/改设置；不得自动挑选设备；不得在 `.fde-ai/runs/` 创建产物；不代提 issue、不发布任何内容。
